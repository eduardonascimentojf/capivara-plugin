Novas Adições da Versão 1.2.0

A versão 1.2.0 expande as capacidades do Capivara, integrando a análise estrutural estática aos dados de execução real gerados por suítes de testes. As principais adições desta versão são:

  • Análise de Cobertura de Nós: Mapeia diretamente as instruções visitadas durante os testes JUnit, destacando blocos de código totalmente executados ou ignorados.
  • Análise de Cobertura de Arestas: Avalia as ramificações lógicas do código, identificando se caminhos condicionais e desvios de fluxo foram de fato exercitados (cenários Verdadeiro/Falso).
  • Exportação dos GFC gerados para PNG: Adiciona um mecanismo de captura interna para salvar o modelo geométrico renderizado em formato de imagem de alta qualidade.
Retrocompatibilidade Garantida: Todas as funcionalidades básicas implementadas na versão anterior (1.1.7), como o parser de código via AST, geração de grafos abstratos e a própria rotina de Node Enumeration, continuam totalmente válidas e operando em conjunto com o novo ecossistema de cobertura.

Como usar a Cobertura no GFC

Para cruzar os dados, o plugin adiciona um menu de contexto dinâmico no editor de código do Eclipse. Basta clicar com o botão direito sobre o método desejado e explorar o painel de cobertura.

Nova Opção de MenuO que faz?
Capivara | Coverage Analysis GFC > Node Coverage Avalia o fluxo com base em instruções executadas de forma estrita, colorindo os nós de processamento.
Capivara | Coverage Analysis GFC > Edge Coverage Avalia o fluxo com foco nas arestas de decisões lógicas, verificando caminhos condicionais.

Legenda de Cobertura dos Nós

Ao ativar o mapeamento dinâmico, o Grafo de Fluxo de Controle (GFC) reajusta as suas cores seguindo estritamente a especificação de diagnóstico do motor de cobertura:

Indicador VisualSignificado Diagnóstico (Padrão EclEmma)
Verde (Covered) Totalmente Coberto: 100% das instruções contidas neste nó estrutural foram exercitadas e validadas com sucesso.
Amarelo (Partial) Linhas Parcialmente Cobertas: Conforme definição oficial do EclEmma, indica que algumas instruções ou ramificações foram omitidas. Isso ocorre tipicamente em nós com condições compostas (ex: if (A && B)). Mesmo que o bloco seja executado, o nó permanece amarelo caso subcombinações lógicas internas da expressão booleana tenham deixado de ser testadas.
Vermelho (Missed) Não Coberto: Alerta máximo. Este trecho de código foi completamente ignorado e nenhuma instrução interna foi disparada pela suíte de testes atual.

Exportação de Diagramas (PNG)

A nova rotina de exportação foi projetada para facilitar a extração de evidências e a elaboração de relatórios acadêmicos ou profissionais. Após organizar a distribuição geométrica dos nós e aplicar os dados de cobertura desejados, você pode salvar o estado atual do grafo:

  1. Clique com o botão direito em qualquer área vazia (fundo) do painel onde o grafo está renderizado.
  2. Selecione a opção Export Diagram as PNG no menu flutuante.
  3. Uma janela nativa do sistema operacional será aberta para que você escolha o diretório de destino e dê um nome ao arquivo.
  4. A imagem será salva preservando a colorização e o score da análise ativa, tornando-se uma ferramenta perfeita para documentação.
